# ระบบดีไซน์ — SWINE SYNC

**บุคลิก: ครีม-ทองพรีเมียม · สว่าง · ตัวหนังสือใหญ่ · สะอาดตา**
ผู้ใช้คือเจ้าของฟาร์ม/คนงานที่ต้องอ่านตัวเลขเร็ว ๆ ทั้งบนจอคอมและมือถือ
ทุกค่าที่ใช้จริงอยู่ใน `src/styles/tokens.css` — เอกสารนี้อธิบาย "วิธีใช้และเหตุผล"

## หลัก 4 ข้อ (ใช้ตัดสินทุกการออกแบบ)

1. **ตัวเลขมาก่อน** — คนเปิดมาเพื่อดูตัวเลข ให้ตัวเลขใหญ่ เด่น อยู่บนสุด ส่วนอธิบายเป็นรอง
2. **อุ่นแต่ไม่จ้า** — พื้นไอวอรี่ (`--bg-page`) + แสงทองจาง ๆ ที่ `body` การ์ดขาวขอบมน เงานุ่มโทนอุ่น
   ไม่มีสีพื้นฉูดฉาด ไม่มี gradient บนการ์ด
3. **สีมีหน้าที่ ไม่ใช่เครื่องประดับ** — ทอง `--accent` ใช้กับสิ่งที่กดได้/เลือกอยู่ + กรอบไอคอน,
   สีสถานะใช้กับสถานะเท่านั้น, สีกราฟใช้แยก series เท่านั้น
4. **น้อยแต่พอ** — หนึ่งหน้าจอไม่ควรเกิน 4 StatTile + 2–4 การ์ด ถ้าข้อมูลเยอะให้แยกหน้า ไม่ใช่ยัดให้แน่น

## ทองใช้ยังไง (สำคัญ — พลาดง่ายที่สุด)

| Token | ใช้กับ | ห้าม |
|---|---|---|
| `--accent` #96681c | ลิงก์ ปุ่มหลัก เมนู active ไอคอนในกรอบ | — (ผ่าน contrast 4.8:1 ใช้กับตัวหนังสือได้) |
| `--accent-strong` | hover/กด | |
| `--accent-tint` | พื้นกรอบไอคอน แถบเมนูที่เลือก | อย่าใช้เป็นพื้นการ์ดทั้งใบ |
| `--accent-bright` #c9a227 | เส้นวงแหวนโลโก้ เส้นตกแต่ง | **ห้ามใช้กับตัวหนังสือ** (contrast ไม่ผ่าน) |

**สีสถานะไม่เปลี่ยนเป็นทอง** — เขียว/เหลือง/ส้ม/แดงคือความคาดหวังสากล ถ้าทำ "เตือน" เป็นทอง
คนจะแยกไม่ออกจากสีแบรนด์

## ธีมและโหมดสี (อ่านก่อนแตะเรื่องสี)

ระบบมีสองแกนที่ **แยกกันเด็ดขาด** เลือกอิสระต่อกันได้ 11 × 20 แบบ:

| แกน | ตัดสินใจว่า | อยู่ที่ไหน |
|---|---|---|
| **ธีมบทบาท** 11 ธีม | *เห็นอะไร* — เมนูบนและกล่องสรุปหน้าภาพรวม | `src/lib/theme/themes.js` (`ROLE_THEMES`) |
| **โหมดโทนสี** 20 โหมด (สว่าง 10 · มืด 10) | *สีอะไร* — สีทั้งแอปรวมถึงสีกราฟ | `src/styles/modes.css` + `COLOR_MODES` |

**ธีมบทบาทห้ามเปลี่ยนสี** — ถ้าปล่อยให้บทบาทมีสีประจำตัว ทองจะไม่ได้แปลว่า "กดได้" อีกต่อไป
ในบางบทบาท ซึ่งพังหลักข้อ 3 ("สีมีหน้าที่ ไม่ใช่เครื่องประดับ") บทบาทคุมเนื้อหา โหมดสีคุมสีเท่านั้น

ทั้งสองแกนปรับได้จากที่เดียว: **ป๊อบอัพตั้งค่า** (`components/settings/SettingsModal.jsx`)
ซึ่งเปิดจากปุ่มเฟืองที่มีอยู่ทุกโครงหน้า — ไม่มีหน้าตั้งค่าแล้ว การตั้งค่าไม่ใช่ "ที่" ที่ต้องมี URL
ค่าเก็บใน localStorage ผ่าน `lib/theme/ThemeProvider.jsx` แล้วทา `data-mode` / `data-scheme` ที่ `<html>`

ค่าอื่นที่ไม่ใช่ธีม (ขนาดตัวอักษร ความหนาแน่น เกณฑ์สถานะ การแจ้งเตือน ค่าไฟ) อยู่คนละที่คือ
`lib/settings/` และคนละคีย์ใน localStorage — ล้างอันหนึ่งไม่กระทบอีกอัน
ขนาดตัวอักษรเป็นตัวคูณต่อเนื่อง `--text-scale` (80–150%) ที่ `--text-*` ทุกตัวคูณอยู่แล้ว
**เพิ่ม token ขนาดตัวอักษรใหม่ต้องเขียนเป็น `calc(ค่าฐาน * var(--text-scale))` เสมอ**
ไม่งั้นตัวนั้นจะไม่ขยายตามที่ผู้ใช้ตั้งไว้

**เพิ่มโหมดสีใหม่ต้องแก้ 2 ที่:** บล็อก `[data-mode="…"]` ใน `modes.css` และรายการใน `themes.js`
แล้วรัน `npm test` — `test/modes.test.js` ตรวจอัตราคอนทราสต์ของทุกโหมดให้อัตโนมัติ
(4.5:1 สำหรับตัวหนังสือ · 3:1 สำหรับไอคอนและเส้นขอบ ตาม WCAG 2.1)
ชื่อโหมดต้องเติมคำแปล en/zh ด้วย เพราะหน้าเลือกโหมดเรียกผ่าน `t()`

### การตั้งค่าที่เขียนทับ token ได้ (`src/lib/settings/`)

ป๊อบอัพตั้งค่า (ปุ่มเฟืองทุกโครงหน้า) เขียนค่าลงบน `<html>` แล้ว `styles/settings.css`
เขียนทับ token ให้ — **component ไม่ต้องรู้เรื่องเลย**:

| เขียนที่ `<html>` | เขียนทับ | ใช้ทำอะไร |
|---|---|---|
| `--text-scale` (ตัวแปร) | `--text-*` ทั้งชุด (คูณอยู่ใน tokens.css) | ขนาดตัวอักษร 80–150% ปรับต่อเนื่องด้วยแถบเลื่อน |
| `data-density` | `--space-3..8` | ความหนาแน่นของเลย์เอาต์ |
| `data-motion="off"` | ปิด animation/transition ทั้งหมด | เท่ากับที่ `prefers-reduced-motion` ทำให้ |

ลำดับ `@import` ใน `base.css` ต้องเป็น **tokens → modes → settings** เสมอ

ส่วนค่าที่เป็น "ตรรกะ" (เกณฑ์สภาพแวดล้อม · ตัวกรองแจ้งเตือน · ค่าไฟ) ส่งผ่าน `useSettings()`
แล้ว**ส่งเข้าไปเป็นพารามิเตอร์** ของฟังก์ชันใน `data/mock/` (เช่น `readingStatus(kind, value, comfort)`)
— ทุกตัวมีค่าตั้งต้นเป็นเกณฑ์เดิมของระบบ ที่เรียกแบบเก่าจึงไม่พัง

### กติกาที่ทำให้โหมดมืดไม่พัง

- **ห้ามเขียน `rgba(255,255,255,…)` / `rgba(62,47,20,…)` ตรง ๆ ใน component** — ใช้
  `rgb(var(--surface-rgb) / .8)`, `rgb(var(--page-rgb) / .5)`, `rgb(var(--shadow-rgb) / .1)`,
  `rgb(var(--scrim-rgb) / .42)` แทน โหมดมืดเปลี่ยนแค่ 4 ค่านี้ ม่านและเงาทั้งแอปก็มืดตามเอง
  (ข้อยกเว้นเดียว: จุดไอคอนที่ลอยอยู่บน **ภาพถ่าย** เสมอ เช่น `.login-photo-chip` — คงขาวไว้)
- สีในกราฟส่งเป็น `var(--token, ค่าสำรอง)` ได้เลย เบราว์เซอร์แทนค่า `var()` ใน
  presentation attribute ของ SVG ให้อยู่แล้ว — `lib/chartTheme.js` ทำแบบนี้ทั้งไฟล์
- ตัวอย่างสีในหน้าตั้งค่าใช้วิธีแปะ `data-mode`/`data-scheme` ของโหมดนั้นลงบน element เล็ก ๆ
  แล้วอ้าง `var(--bg-page)` ตามปกติ — สีตัวอย่างจึงตรงกับของจริงเสมอ ไม่ต้องก๊อป hex มาไว้ใน JS

## ไอคอน

ทุกไอคอนมาจาก `components/ui/Icon.jsx` ที่เดียว — เส้นบาง 1.7px บน viewBox 24×24 `currentColor`
**ห้ามใช้ emoji และห้ามผสมไอคอนต่างสไตล์** (เคยใช้ emoji ในเมนู เปลี่ยนออกทั้งชุดแล้ว)
ถ้าต้องการไอคอนใหม่ให้เพิ่มใน `PATHS` และวาดให้อ่านออกที่ขนาด 18px —
รูปที่รายละเอียดเยอะจะเละตอนย่อ (เคยวาดหน้าหมูเต็มตัวแล้วไม่รอด เลยเหลือแค่จมูกหมู)

กรอบไอคอน (`.icon-chip`) ใช้หน้าหัวการ์ดและมุมขวาบนของ StatTile — พื้น `--accent-tint` ไอคอน `--accent`

### ความสูงบรรทัด (วัดมาแล้ว — ห้ามลดลง)

ฟอนต์ `Noto Sans Thai` มีระยะเหนือ-ใต้ตัวอักษรมาก (สระบน + วรรณยุกต์ + สระล่าง)
**ข้อความภาษาไทยต้องใช้ `line-height` อย่างน้อย 1.5** — ต่ำกว่านี้ขอบตัวอักษรจะถูกตัด
และวรรณยุกต์บรรทัดล่างจะชนสระล่างของบรรทัดบน (ทดสอบที่ 42px: 1.35→ล้น 3px, 1.5→พอดี)
ยกเว้นเฉพาะข้อความอังกฤษ/ตัวเลขล้วน เช่น ชื่อแบรนด์ "SWINE SYNC" ใช้ 1.25 ได้
ตัวเลขคู่กับหน่วยภาษาไทย ให้ใช้ `display:flex; align-items:baseline` แทนการปล่อยเป็น inline

## สีพื้นและโครงหน้า

- พื้นหน้า `--bg-page` (#faf8f3 ไอวอรี่อุ่น) + แสงทองสองจุดที่ `body` (ดู `base.css`)
  การ์ด `--bg-surface` (ขาว) / ขอบ `--border` (โทนอุ่น) / เงา `--shadow-card` (นุ่ม ไม่ดำ)
- มุมโค้ง: การ์ด `--radius-lg` (20px), ปุ่ม/badge `--radius-md` (14px), กรอบไอคอน `--radius-sm` (10px)
- ระยะห่างใช้ `--space-1..8` เท่านั้น อย่ากลัวพื้นที่ว่าง — ความโปร่งคือความสะอาดตา

### โครงทุกหน้า (ดู `pages/Overview.jsx` เป็นแบบ)

```
<PageHeader title subtitle />
<div className="tile-grid">   ← แถว StatTile 2–4 ใบ (จอกลางบังคับ 2×2, จอเล็กคอลัมน์เดียว)
<div className="card-grid">   ← การ์ดกราฟ/ตาราง (auto-fit, กว้างขั้นต่ำ 460px)
<Card className="stack-block"> ← บล็อกเต็มความกว้าง (แผนที่/ตารางยาว)
```

**Card รับ `icon` และ `action`** — `icon` ขึ้นเป็นกรอบไอคอนหน้าหัวการ์ด,
`action={{ to, label, icon }}` เป็นลิงก์ท้ายการ์ดที่ดันไปชิดล่างเสมอ (การ์ดในแถวเดียวกันจะเรียงตรงกัน)
ตารางที่กว้างเกินจอต้องห่อด้วย `<div className="table-scroll">` — ให้เลื่อนในตัวเอง ห้ามดันทั้งหน้า

Responsive จัดการโดย grid + `AppLayout` แล้ว

**แถบเมนูซ้ายเป็นแผงเลื่อนเข้า ปิดไว้เป็นค่าตั้งต้นทุกหน้า** (ผู้ใช้สั่ง 2 ก.ย. 2569)
เปิดด้วยปุ่มขีดสามขีดที่อยู่หน้าโลโก้บนแถบบน — แผงลอยทับเนื้อหา ไม่ดันเนื้อหา
ทำแบบเดียวกันทุกขนาดจอ ไม่มีท่าพิเศษสำหรับจอแคบอีกแล้ว
`--side-w` ตอนนี้คุมแค่ความกว้างของแผง ไม่ได้คุมความกว้างเนื้อหาแล้ว
— หน้าเพจไม่ต้องเขียน media query เองถ้าใช้ `tile-grid` / `card-grid`

## ความลึก (สามมิติ)

ความลึกในแอปนี้มาจาก **เงาซ้อนชั้น** อย่างเดียว ไม่ใช่ gradient สี ไม่ใช่การเอียงมุมมอง
(กราฟยังต้องแบนเสมอ — "กราฟ 3D" อยู่ในข้อห้ามด้านล่าง)

- `--shadow-3d` / `--shadow-3d-hover` — **แผ่นนูน** ที่ลอยขึ้นจากพื้น มีเส้นสว่างขอบบน
- `--shadow-3d-chip` — ชิ้นเล็กที่นูนเบา ๆ (วงกลมไอคอน, ชิป, แถวในลิสต์)
- `--shadow-well` — **พื้นจม** ตรงข้ามกับแผ่นนูน ใช้กับ "ถาด" ที่มีแผ่นวางอยู่ข้างใน
  รางของหลอดค่า และแถบสรุปที่อยากให้ดูฝังลงไปในการ์ด
- คู่ที่อ่านง่ายที่สุดคือ **ถาดจม + แผ่นนูน** (ดูส่วน "อากาศตอนนี้" ในหน้าสภาพแวดล้อม)
  ห้ามซ้อนนูนบนนูนหลายชั้นจนไม่รู้ว่าอะไรอยู่ระดับไหน
- เงานูนยังแปลว่า "กดได้" อยู่เหมือนเดิม — แผ่นที่กดไม่ได้ใช้เงาระดับเดียวกันได้
  แต่ห้ามยกขึ้นตอนชี้ (`transform`) เพราะการขยับคือสัญญาณว่ากดได้

## ผิวกระจก-ฮอโลแกรม (T1.357 · ขยายใน T1.361)

ผิวของกระดาน — แผงควบคุมอุตสาหกรรมผสมกระจกฝ้า นูนนุ่ม และฮอโลแกรม
อยู่ที่ **`styles/skin.css`** (นำเข้าใน `base.css` ต่อจาก settings)

### ★★ เพิ่มหน้าใหม่ให้เติมที่ `lib/layout/skin.js` ที่เดียว

```js
export const SKINNED_BOARDS = ["overview", "alerts"];
```

กระดานติดคลาส `is-skinned` ให้เอง แล้ว CSS ทำงานตามทันที
**ห้ามกลับไปเล็ง `data-board` ทีละหน้าใน CSS** — ทุกกฎจะต้องต่อรายชื่อหน้าเพิ่มทุกกฎ
พลาดกฎเดียวหน้าใหม่ได้ผิวไม่ครบแล้วไม่มีอะไรฟ้อง

★ ไม่ได้ให้ทุกหน้าโดยตั้งใจ — หน้าที่เป็นตารางยาวหรือฟอร์ม กระจกไม่ช่วยให้อ่านง่ายขึ้น
และ `backdrop-filter` หลายใบพร้อมกันกินแรงเครื่องฟรี ๆ

### ★ ไทล์สรุปของแต่ละหน้าใช้คลาสคนละชื่อ

หน้าภาพรวมใช้ `.stat-tile` หน้าการแจ้งเตือนมี `.al-kpi` ของตัวเอง
`skin.css` เล็งทั้งสองชื่อไว้ที่เดียว ดีกว่าก๊อปกฎทั้งชุดไปไว้ในไฟล์ของแต่ละหน้า

### ★★ แผงฮีโร่อยู่ที่ `pages/Overview.css` ไม่ใช่ `skin.css`

เพราะฮีโร่เป็นของหน้าเดียว และสำคัญกว่านั้นคือ `base.css` โหลด**ก่อน**ไฟล์ของหน้า
ถ้าเอากฎกระจกของฮีโร่ไปไว้ใน `skin.css` กฎตั้งต้น `.ov-hero { background: var(--bg-surface) }`
ในไฟล์ของหน้าจะเขียนทับทิ้งทั้งหมด แล้วฮีโร่กลับเป็นการ์ดขาวโดยไม่มีอะไรฟ้อง
— เจอจริงตอนแยกไฟล์

### ★★ "ผิว" คนละแกนกับ "โหมดสี" และ "ธีมบทบาท"

| แกน | ตัดสินใจว่า |
|---|---|
| ธีมบทบาท | เห็นอะไร |
| โหมดสี | สีอะไร |
| **ผิว** | **พื้นผิวแบบไหน** — ความโปร่ง ขอบ เงา ของประดับ |

ผิวแตะเฉพาะ **พื้นผิว · ขอบ · เงา** เท่านั้น
**ไม่แตะ `--ink-*` `--status-*` และสีกราฟเลยสักตัว** คอนทราสต์ของทั้ง 20 โหมดจึงเท่าเดิม
และ `test/modes.test.js` ยังผ่านเหมือนเดิมโดยไม่ต้องแก้อะไร

### token ของผิว (`tokens.css` + คู่โหมดมืดใน `modes.css`)

| token | ใช้ทำอะไร |
|---|---|
| `--glass-bg` `--glass-blur` | พื้นกระจกและความฟุ้งหลังกระจก |
| `--glass-rim` `--glass-edge` | เส้นขอบในที่ทำให้ตาอ่านว่าเป็น "แผ่นกระจก" |
| `--glass-shadow(-hover)` | เงากระจก ใช้แทน `--shadow-3d` บนหน้านี้ |
| `--holo-rim` `--holo-sheen` | แถบสะท้อนและแสงกวาดตอนชี้ |
| `--holo-tick` | ขีดมุมแบบหน้าปัดเครื่องจักร |
| `--grid-ink` `--grid-size` | ตารางแผงควบคุม |
| `--neu-raise` | เงานูนนุ่มแบบ neumorphism |

**สีสะท้อนประกอบจาก token ที่มีอยู่ด้วย `color-mix`** (`--accent-bright` · `--series-1`
· `--pink-soft`) ไม่ได้เขียน hex ใหม่ — เปลี่ยนโหมดสีเมื่อไหร่ แสงสะท้อนเปลี่ยนตามเอง
ไม่ต้องมาเติมทีละโหมด

### กติกาของผิวนี้

- **ของประดับห้ามแบกความหมาย** ทุกชิ้นเป็น pseudo-element และถูกตัดทิ้งทั้งหมด
  เมื่อผู้ใช้ปิดการเคลื่อนไหว — สถานะยังต้องผ่าน `StatusBadge` เหมือนเดิมทุกประการ
- **แสงกวาดวิ่งครั้งเดียวจบ ห้ามวิ่งวน** ของที่ขยับตลอดเวลาจะดึงสายตาออกจากตัวเลข
  ซึ่งเป็นสิ่งเดียวที่หน้านี้มีไว้ให้อ่าน
- **ความทึบของกระจกปรับจากการมองจริงบนหน้าจอ** ทึบกว่า 0.86 ดูเหมือนการ์ดขาวธรรมดา
  ใสกว่า 0.74 ภาพพื้นหลังแย่งสายตากับตัวเลข
- **จอแคบ (< 900px) ทึบขึ้นและตัด `backdrop-filter` ทิ้ง** เพราะกระจกฝ้าหลายใบพร้อมกัน
  กินแรงเครื่องจริงบนมือถือ — ทึบขึ้นด้วยการ**เขียนทับ token `--glass-bg`** ไม่ใช่เขียนทับ
  `background` ของแต่ละกล่อง เพราะ `background` แบบย่อจะล้างขีดมุมไปด้วย
- ★ **`.card` กับ `.stat-tile` เป็นกล่องเดียวกันได้** กล่องสรุปมีคลาส `card` ติดมาด้วย
  กฎที่เล็งการ์ดบนหน้านี้จึงต้องเป็น `.card:not(.stat-tile)` เสมอ
  (เคยพลาดมาแล้ว: ขีดมุมหายเกลี้ยงทั้งที่กฎถูกทุกอย่าง เพราะกฎการ์ดเขียนทับพื้นของกล่องสรุป)

## ปุ่มและฟอร์ม (หน้าแรก + หน้าเข้าสู่ระบบ)

- **ปุ่มที่กดได้ต้องดูนูน** — ใช้ `--shadow-raised` (ปุ่มขาว) หรือ `--shadow-raised-gold` (ปุ่มทองหลัก)
  hover ยก `translateY(-2px)` · กดยุบ `translateY(2–3px)` + เปลี่ยนเป็นเงา `*-press`
  ห้ามใช้เงานูนกับสิ่งที่กดไม่ได้ (เงานูน = สัญญาณว่ากดได้)
- ปุ่มทองมีได้ **ปุ่มเดียวต่อพื้นที่สายตา** — ที่เหลือเป็นปุ่มขาวขอบบาง
- **ช่องกรอก**: `.login-control` เป็นแบบอ้างอิง — กรอบ `--radius-md` + ไอคอนนำหน้าสีทอง,
  ตอน focus ใช้ `border-color: var(--accent)` + วงแหวน `box-shadow 0 0 0 3px var(--accent-tint)`
  ห้ามใช้ outline ฟ้าเริ่มต้นของเบราว์เซอร์ และห้ามพึ่ง placeholder แทน label (ต้องมี label เสมอ)
- **ข้อความผิดพลาดต้องมีไอคอน + ข้อความ** (`Icon name="warn"` + พื้น `--status-critical-bg`)
  และผูกกับฟอร์มด้วย `role="alert"` ห้ามบอกด้วยกรอบแดงเฉย ๆ

## ป๊อบอัพ (`components/ui/Modal.jsx`)

ใช้เมื่อผู้ใช้ต้อง **เลือกอะไรก่อนไปต่อ** (เช่น เลือกฟาร์ม/โรงเรือนก่อนเข้าหน้าอุณหภูมิ)
ห้ามใช้แทนหน้าเต็มสำหรับเนื้อหายาว ๆ และห้ามซ้อนป๊อบอัพในป๊อบอัพ

1. ต้องปิดได้ **3 ทางเสมอ**: ปุ่มกากบาท · กดพื้นหลัง · ปุ่ม Esc
2. `role="dialog"` + `aria-modal="true"` + `aria-labelledby` ชี้ไปที่หัวกล่อง
3. โฟกัสต้องถูกขังไว้ในกล่อง (Tab วนกลับ) และคืนให้ปุ่มที่เปิดกล่องเมื่อปิด
4. ล็อกการเลื่อนหน้าด้านหลังระหว่างเปิด และคืนค่าเดิมเมื่อปิด
5. ปุ่มท้ายกล่องใช้ `.modal-btn` — ปุ่มทอง (`is-primary`) ได้ **ใบเดียว** และปิดการใช้งาน
   จนกว่าผู้ใช้จะเลือกครบ (ห้ามให้กดแล้วเงียบ)
6. ไทล์/ปุ่มที่เปิดป๊อบอัพใช้ `aria-haspopup="dialog"` ไม่ใช่ `aria-pressed`
   (`StatTile` มี prop `haspopup` ให้แล้ว)
7. แบบ **หัวกลาง + ภาพประกอบ**: `align="center"` + `art={...}` + `size="sm"`
   ภาพประกอบวาดเป็น SVG ในโค้ด (เช่น `PickerScene`) หรือวางไฟล์จริงแล้ว fallback มาที่ SVG
8. เลือกของหลายขั้นให้เรียง **ซ้าย→ขวา** คั่นด้วยเส้นตั้ง + ลูกศร และวางทั้งบล็อกบน grid เดียว
   (`grid-area` กำหนดตำแหน่ง) เพื่อให้หัวข้อ/ช่องเลือก/การ์ดของทั้งสองฝั่งอยู่ระดับเดียวกันเป๊ะ
   จอแคบกว่า 720px ให้ยุบเป็นคอลัมน์เดียวและซ่อนเส้นคั่น

## สถานะ

ใช้ `StatusBadge` เสมอ (ไอคอน + ข้อความ + สี — ครบสามอย่าง):
`good` ปกติ · `warning` เฝ้าระวัง · `serious` ต้องจัดการ · `critical` วิกฤต ·
`offline` ไม่มีสัญญาณ (เทา — แปลว่า "ไม่รู้" ไม่ใช่ "แย่" อย่าใช้แทน critical)
สีสถานะ **ห้าม** เอาไปใช้เป็นสีกราฟ series และห้ามใช้เขียว accent แทน `--status-good`
ข้อความสีสถานะบนพื้นสว่างให้ใช้ชุด `--status-*-text` (เข้มกว่า อ่านออก)

## ที่มาของข้อมูล (`DataSourceBadge`) — คนละเรื่องกับสถานะ

**ตัวเลขทุกตัวบนจอต้องบอกได้ว่ามาจากไหน** ตอนนี้มีฟาร์มที่ต่อเซนเซอร์จริงอยู่ฟาร์มเดียว
ที่เหลือเป็นข้อมูลตัวอย่าง ถ้าไม่ติดป้าย คนจะเอาเลขสมมติไปตัดสินใจ (เคยเกิดจริงในหน้าภาพรวม:
กล่อง "กำไรเดือนล่าสุด" เป็นเลขสมมติล้วนแต่ไม่มีอะไรบอกเลย — T1.281)

| ค่า | ป้าย | ใช้เมื่อ |
| --- | --- | --- |
| `live` | ข้อมูลจริง (เขียว) | ทุกตัวเลขในก้อนนั้นมาจากเซนเซอร์จริง |
| `mixed` | จริง + ตัวอย่าง (ทอง) | **ตัวเลขรวมที่มีทั้งสองแบบปนกัน** เช่นยอดรวมทุกฟาร์ม |
| `demo` | ข้อมูลตัวอย่าง (เทา) | เลขสมมติล้วน · ไม่มีข้อมูลให้ยืนยันก็นับเป็นอันนี้ |

- **ห้ามเขียนค่านี้ตายตัวถ้าคำนวณได้** ใช้ `blendSource(hasReal, hasSample)` จาก
  `lib/records/dataSource.js` ป้ายจะได้เปลี่ยนเองเมื่อผู้ใช้ลบฟาร์มตัวอย่าง หรือเมื่อต่อเซนเซอร์เพิ่ม
- `StatTile` รับ prop `source` — **กล่องสรุปที่โชว์ตัวเลขต้องส่งมาเสมอ**
  (มีเทสต์คุมไว้ว่าทุกกล่องในหน้าภาพรวมต้องประกาศ)
- **ทั้งหน้าเป็นข้อมูลตัวอย่าง ใช้ `DataSourceNote` เพิ่มด้วย** — ป้ายบอกได้ว่ากล่องไหนเป็นอะไร
  แต่ไม่ได้บอกว่าควรทำยังไงกับตัวเลข วางไว้**ก่อน**ตัวเลขเสมอ ไม่ใช่ท้ายหน้า
  (`source="demo"` ทั้งหน้าเป็นของสมมติ · `source="mixed"` ปนกัน)
- ไม่ใช่สถานะของฟาร์ม จึงเบากว่า `StatusBadge` โดยตั้งใจ — แต่ยังมีไอคอน + ข้อความครบเหมือนกัน
- `mixed` ใช้ไอคอนเดียวกับ `demo` เพราะสิ่งที่ต้องระวังเป็นเรื่องเดียวกัน (มีเลขสมมติปนอยู่)
  ตัวที่บอกว่าปนแค่ไหนคือข้อความ

## กราฟ (สำคัญที่สุด — อ่านให้จบ)

ใช้ Recharts + ค่าจาก `lib/chartTheme.js` เท่านั้น

**เลือกชนิดกราฟจากหน้าที่ของข้อมูล:**
- ตัวเลขเดียวสำคัญ → ไม่ต้องเป็นกราฟ ใช้ StatTile
- แนวโน้มตามเวลา → เส้น (Line) หนา 2px, จุด dot เล็ก
- เปรียบเทียบปริมาณระหว่างกลุ่ม → แท่ง (Bar) มุมบนโค้ง 4px, ช่องว่างระหว่างแท่ง
- ส่วนประกอบของยอดรวมตามเวลา → แท่งซ้อน (Stacked bar) มีช่อง 2px ระหว่างชั้น
- สัดส่วน ณ จุดเดียว → แท่งแนวนอนเรียงค่า (ไม่ใช้ pie ถ้าเกิน 3 ชิ้น)

**กติกาบังคับ:**
1. **แกน Y เดียวเท่านั้น** สองหน่วย = สองกราฟ (นี่คือข้อผิดพลาดอันดับหนึ่ง)
2. สี series เรียงตาม `SERIES` ใน chartTheme ห้ามข้าม ห้ามสุ่ม — ลำดับนี้ผ่านการตรวจตาบอดสีแล้ว
3. **สีผูกกับสิ่งของ ไม่ใช่ลำดับ**: โรงเรือน B4=SERIES[0], B5=SERIES[1], B6=SERIES[2] ทุกกราฟ;
   หมวดต้นทุนใช้ `COST_COLORS` — กรองข้อมูลแล้วสีต้องไม่เปลี่ยน
4. ≥ 2 series ต้องมี legend เสมอ (series เดียวไม่ต้อง — ชื่อการ์ดบอกอยู่แล้ว)
   ใช้ `components/ui/ChartLegend.jsx` ไม่ใช่ `<Legend/>` ของ Recharts — ของ Recharts
   เรียงลำดับแท่งซ้อนสลับกับชั้นจริง (prop `payload` ก็ไม่มีผล) และทาสี series ลงบนตัวหนังสือ
5. กริดใช้ `gridProps` (เส้นนอนจาง ๆ อย่างเดียว), แกนใช้ `axisProps`, tooltip ใช้ `tooltipStyle`
6. ทุกกราฟต้องมี tooltip ตอน hover พร้อมหน่วย เช่น "2,370 กก."
7. ไม่แปะตัวเลขบนทุกจุด — ถ้าจำเป็นให้ label เฉพาะจุดสำคัญ หรือทำตารางประกอบ
8. เหลือง/เขียวทะเล/ชมพู (SERIES 2,3,7) จางบนพื้นขาว → ถ้าใช้เป็น series หลักต้องมี legend + tooltip ครบ
9. ยอดรวมมาก/น้อยแบบไล่ระดับ (heatmap) ใช้ `--seq-*` สีเดียวไล่อ่อน→เข้ม ห้ามรุ้ง
10. แถบ "ช่วงที่เหมาะสม" ในกราฟใช้ `comfortBandProps` (ReferenceArea) เท่านั้น
    และต้องมี `isFront: false` เสมอ ไม่งั้นแถบจะทับเส้นกราฟจนมองไม่เห็น
11. ค่าเซนเซอร์ค่าเดียวที่ต้องเทียบกับช่วงที่ควรเป็น ใช้เกจครึ่งวงกลม `ClimateGauge`
    (ภาพแบน ไม่ใช่กราฟ 3 มิติ) — ถ้าไม่ต้องเทียบช่วง ใช้ `StatTile` พอ
12. สีผูกถาวรเพิ่ม: **อุณหภูมิ = SERIES[7] (ส้ม) · ความชื้น = SERIES[0] (น้ำเงิน)** ห้ามสลับ

## แผนที่ (`components/map/FarmMap.jsx`)

แผนที่เขียนเองด้วย raster tile + Web Mercator ไม่ได้ใช้ library แผนที่ (Leaflet/Mapbox)
เพื่อไม่ให้ผิดกติกา "ห้ามเพิ่ม dependency" — โครงคิดเหมือน Leaflet ทุกอย่าง

**กติกา:**
1. **ต้องแสดง attribution เสมอ** (`© OpenStreetMap · © CARTO`) เป็นเงื่อนไขของผู้ให้บริการ tile
   ถ้าเปลี่ยนผู้ให้บริการให้แก้ `TILE_URL` ที่เดียว แล้วแก้ข้อความเครดิตตาม
2. **สีหมุด = สีสถานะ** (`--status-good/warning/offline`) และต้องมีป้ายข้อความชื่อฟาร์มคู่เสมอ
   ห้ามสื่อสถานะด้วยสีหมุดอย่างเดียว — คนตาบอดสีต้องอ่านออกจากป้าย/แถบข้าง
3. **หมุดที่อยู่ใกล้กันเกิน 36px จะถูกรวมเป็นกลุ่ม** (`clusterPoints`) กดแล้วซูมเข้าเพื่อแยก
   อย่าแก้ปัญหาหมุดทับกันด้วยการขยับพิกัดให้ผิดจากความจริง
4. ป้ายชื่อสลับซ้าย/ขวาอัตโนมัติ (`placeLabels`) เพื่อไม่ให้ทับกัน — จอแคบซ่อนป้ายที่ไม่ได้เลือก
5. ล้อเมาส์ซูมได้เฉพาะตอนกด Ctrl/⌘ ค้าง ไม่งั้นแผนที่จะแย่งการเลื่อนหน้าเพจ
6. ความสูงแผนที่ใช้ `--map-h` ไม่ใช่ค่าเฉพาะกิจ

  ที่ใช้ได้กับ **ปุ่มหลักใบเดียวของหน้าเท่านั้น** ห้ามเอาไปใส่พื้นการ์ดหรือแถบใด ๆ)
- เขียว `--green` / `--green-tint` / `--green-strong` เป็นสีตกแต่ง UI (ป้ายลำดับขั้น ชิปข้อมูล)
  **ห้ามใช้สื่อความหมาย "สถานะดี"** — สถานะต้องผ่าน `StatusBadge` + `--status-*` เสมอ
- กราฟ 3D, pie มีเงา, สีรุ้ง, ตัวเลขทุกจุดบนกราฟ
- **emoji และไอคอนคนละสไตล์ปนกัน** — ใช้ `Icon.jsx` เท่านั้น
- ตัวหนังสือสีแดง/เขียวทั้งประโยค (ใช้ badge หรือ delta สั้น ๆ แทน)
- ทองสว่าง (`--accent-bright`) กับตัวหนังสือ — อ่านไม่ออกบนพื้นขาว
