# โฟลว์ Node-RED (สำเนาสำหรับส่งมอบ)

`flows.json` ที่นี่คือ **สำเนา** ของไฟล์จริงที่ `~/.node-red/flows.json` บนเครื่องที่รับค่าเซนเซอร์
เก็บไว้ใน repo เพื่อให้คนที่มารับช่วงต่อเห็นได้ว่าท่อข้อมูลต่อกันยังไง โดยไม่ต้องเข้าเครื่องนั้นก่อน

**ไม่มีรหัสผ่านหรือ token ในไฟล์นี้** — ของพวกนั้นอยู่ใน `flows_cred.json` ที่ Node-RED เข้ารหัสไว้
และ **ห้ามเอาขึ้น repo**

## ของจริงอยู่ที่ไหน

| อะไร | ที่ไหน |
| --- | --- |
| ไฟล์โฟลว์จริง | `~/.node-red/flows.json` บนเครื่องผู้พัฒนา |
| เปิดหน้าแก้โฟลว์ | `http://localhost:1880` |
| log | `~/Library/Logs/swinesync-nodered.log` |
| บริการที่เปิดให้เอง | `~/Library/LaunchAgents/com.swinesync.nodered.plist` |

## แท็บที่ใช้จริง

**`PRUK-work`** คือแท็บที่ใช้อยู่ — รับ MQTT 6 หัวข้อของฟาร์มแล้วเขียนลง InfluxDB bucket `climatesensor`
แท็บ `PRUK` เป็นของเดิมและ **ปิดอยู่** (`disabled: true`) ห้ามเปิดพร้อมกัน ไม่งั้นข้อมูลจะถูกเขียนซ้ำสองชุด

## เอาสำเนานี้กลับขึ้นเครื่องยังไง

```bash
cp ops/node-red/flows.json ~/.node-red/flows.json
launchctl kickstart -k "gui/$(id -u)/com.swinesync.nodered"
```

อัปเดตสำเนาหลังแก้โฟลว์บนเครื่อง: `cp ~/.node-red/flows.json ops/node-red/flows.json`
(ไม่มีตัวซิงก์อัตโนมัติ — ถ้าแก้บนเครื่องแล้วไม่ก๊อปมา สำเนานี้จะเก่าเงียบ ๆ)

## `control-outbox.json` — ส่งคำสั่งจากแดชบอร์ดไปตู้ควบคุม (T1.310)

โฟลว์แยกต่างหาก **นำเข้าแล้วยังไม่ทำงานทันที** (แท็บถูกตั้งเป็น disabled ไว้)

### ทำไมคำสั่งต้องเดินทางแบบ "ให้มาดึง"

API ที่รับคำสั่งรันอยู่ใน**กล่อง** ส่วน Node-RED อยู่บน**เครื่องผู้พัฒนา**
และ **กล่องต่อมาหาเครื่องผู้พัฒนาไม่ได้** (tailscaled ในกล่องเป็น userspace-networking)
ส่วนทิศทางเครื่องผู้พัฒนา → กล่อง ใช้ได้ปกติ Node-RED จึงเป็นฝ่ายมาถามเองทุก 5 วินาที

★ อีกทางคือให้กล่อง publish ขึ้น broker แล้ว Node-RED subscribe
**ไม่เลือกทางนั้นเพราะถ้าใช้ broker สาธารณะ ใครก็ publish คำสั่งปลอมเข้า topic เดียวกันได้**
แล้ว Node-RED จะส่งต่อให้ PLC โดยไม่รู้ว่าไม่ใช่ของเรา

### ขั้นตอนเปิดใช้

1. **ฝั่งกล่อง** ตั้งใน `.env` แล้วรีสตาร์ต API
   ```
   CONTROL_TRANSPORT=outbox
   CONTROL_OUTBOX_TOKEN=<สุ่มมาสักยาว ๆ>
   ```
2. **นำเข้าโฟลว์** Node-RED → เมนู → Import → เลือกไฟล์นี้
3. **ตั้ง tab env** `API_BASE` (ที่อยู่กล่อง) และ `OUTBOX_TOKEN` (ให้ตรงกับข้อ 1)
4. **เติมตัวแปลงใน node “แปลงเป็นภาษา PLC”** — ดูหัวข้อถัดไป
5. **ตั้ง broker** ของ node “ส่งให้ PLC” ให้ชี้ broker ของฟาร์ม
6. ค่อยเปิดแท็บ

### ★ node “แปลงเป็นภาษา PLC” คือส่วนที่ต้องเติมเอง

ในนั้นมีตัวแปร `MAPPED = false` อยู่ **ตราบใดที่ยังเป็น false โฟลว์จะไม่ส่งอะไรออกไปเลย**
แต่จะรายงานกลับว่า "ยังไม่ได้ตั้งค่าตัวแปลง" ซึ่งจะไปโผล่ในหน้าแจ้งเตือนของแดชบอร์ด

ทำแบบนี้เพราะ **เดา topic/payload ของ PLC ไม่ได้** — เดาผิดแล้วโชคดีคือไม่มีอะไรเกิดขึ้น
เดาผิดแล้วโชคร้ายคือพัดลมในโรงเรือนจริงหยุดหมุน

ต้องได้สเปกจากเจ้าของระบบสภาพแวดล้อมก่อนสามข้อ
- topic ที่ PLC ฟังอยู่
- payload หน้าตาแบบไหน (JSON / ตัวเลขดิบ / สตริง)
- ความเร็วพัดลมใช้หน่วยอะไร (Hz / เปอร์เซ็นต์ / ระดับ)

### สิ่งที่โฟลว์นี้ทำไม่ได้

- **ไม่เหมาะกับการสั่งหยุดฉุกเฉิน** — ช้าได้ถึง 5 วินาที ของแบบนั้นต้องมีสวิตช์จริงที่หน้างาน
- **ไม่รู้ว่าตู้ทำตามหรือเปล่า** — รายงานว่า "ส่งแล้ว" เท่านั้น
  การยืนยันว่าพัดลมหมุนจริงต้องมีช่องทางตอบกลับซึ่งยังไม่มี
