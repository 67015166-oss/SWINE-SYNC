เก็บ **ค่าเซนเซอร์จากกล่อง box-mew** กับ **อากาศภายนอกจากภายนอก** ไว้ที่เดียวกัน

**ไฟล์นี้เป็นคู่มืออ้างอิงเร็ว** — เปิดหาคำสั่งแล้วปิด

## 3. เติมข้อมูลย้อนหลัง

ตัวเก็บข้อมูลเริ่มนับหนึ่งจากวันที่เปิดใช้ ส่วนของก่อนหน้านั้นต้องดึงมาใส่เอง
**ควรทำทันทีหลังเปิดระบบครั้งแรก** เพราะโมเดลต้องเห็นรอบวันหลาย ๆ รอบถึงจะเรียนรู้ได้

```bash
# ทั้งสองทางรวดเดียว — ค่าเซนเซอร์จากฐานแดชบอร์ด แล้วตามด้วยอากาศย้อนหลัง 400 วัน
docker compose exec wx-collector node src/backfill.js all
```

หรือแยกทำทีละทาง

| คำสั่ง | ได้อะไร |
| --- | --- |
| `node src/backfill.js archive 400` | อากาศภายนอกย้อนหลัง 400 วัน จากคลัง ERA5 |
| `node src/backfill.js swine-db` | ค่าเซนเซอร์ดิบจากฐานของแดชบอร์ด (ก.ค. 2569 เป็นต้นมา) |
| `node src/backfill.js csv ไฟล์.csv` | ค่าเซนเซอร์จาก CSV ที่โหลดจากเว็บพี่เลี้ยง |

### เรื่อง CSV — ทำไมต้องโหลดเอง

`/api/series` ของพี่เลี้ยง **บีบข้อมูลให้เหลือประมาณ 120 จุดเสมอ** ไม่ว่าขอช่วงยาวแค่ไหน

| ขอ | ได้ | ห่างกันจุดละ |
| --- | --- | --- |
| 24 ชม. | 121 จุด | 12 นาที |
| 30 วัน | 112 จุด | 6 ชั่วโมง |
| 1 ปี | 22 จุด | 73 ชั่วโมง |

ยอดแหลมถูกเฉลี่ยกลืนไปหมด ซึ่งเป็นสิ่งที่โมเดลพยากรณ์ต้องการมากที่สุด
**ข้อมูลดิบย้อนหลังจึงเอาผ่าน API ไม่ได้** ต้องโหลด CSV จากเว็บ (ต้องล็อกอิน):

> เข้า lab.plotnexuslab.com → **ดูข้อมูล** → เลื่อนลงหา **โหลดเป็นไฟล์ CSV**
> → ชุดข้อมูล `กำแพงเพชร (เล้าหมู + เสาอากาศ)` → ตาราง **`data_realtime_raw`**
> → เลือกช่วงเวลา → กด **นับก่อนโหลด** ดูจำนวนแถวก่อน (จำกัด 200,000 แถวต่อครั้ง)

#### ต้องเป็น `data_realtime_raw` เท่านั้น — เคยพลาดมาแล้วและมองไม่เห็นด้วยตา

ชุดข้อมูลหนึ่งมี 12 ตาราง และ **ไฟล์ที่ export ออกมาหัวคอลัมน์เหมือนกันหมด**
แยกไม่ออกว่ามาจากตารางไหน ต่างกันแค่ชื่อไฟล์

| ตาราง | ข้างในคืออะไร | ใช้เทรนได้ไหม |
| --- | --- | --- |
| `data_realtime_raw` | ค่าที่วัดได้จริงทุกครั้ง | **ใช่ — เอาตัวนี้** |
| `data_Min_Max_Mean_Avg_3hr` | ค่าเฉลี่ยย้อนหลัง 3 ชม. เลื่อนทีละ 5 นาที | ไม่ |
| `…_6hrs` · `…_12hrs` · `…_24hrs` · `…_7day` · `…_1monuth` | เหมือนกัน แค่หน้าต่างยาวขึ้น | ไม่ |
| `data_filter` · `data_fliter_ema` · `data_fliter_regression_20value` | ผ่านตัวกรองมาแล้ว | ยังไม่ได้ตรวจ |

ชื่อ `12hrs` **ไม่ได้แปลว่า "ออกไฟล์ทุก 12 ชั่วโมง"** แต่แปลว่า
“ค่าเฉลี่ยย้อนหลัง 12 ชั่วโมง” — เข้าใจผิดตรงนี้แล้วนำเข้าไป 9 ไฟล์
กว่าจะจับได้ก็ตอนเทียบเซนเซอร์แสง

```
เซนเซอร์ตัวเดียวกัน ในเล้า        ของดิบ      จาก _12hrs
  ขึ้นสูงสุดตอน                   บ่ายโมง      2 ทุ่ม
  แกว่งทั้งวัน                     3.6 °C      0.7 °C
เซนเซอร์แสงที่ฟาร์ม ตอน 3 ทุ่ม        0 lux      505 lux
```

โมเดลที่เทรนบนข้อมูลนั้นได้คะแนนสวยเกินจริง เพราะเส้นที่ถูกเกลี่ยแล้วทำนายง่ายกว่ามาก
ตอนนี้ `backfill.js` **ปฏิเสธไฟล์แบบนั้นให้เองแล้ว** โดยดูคอลัมน์ `count`
(ของดิบ = 1 · ของสรุป = 36 · 72 · 144 …) ถ้าอยากฝืนต้องใส่ `--force` เอง

เอาไฟล์ที่ได้มาวางใน `weather/lab/exports/` แล้วสั่ง

```bash
docker compose exec wx-collector node src/backfill.js csv /work/exports/ชื่อไฟล์.csv
```

> ตัวอ่าน CSV เขียนแบบเดาหัวคอลัมน์ให้ ถ้าอ่านไม่ออกจะพิมพ์หัวคอลัมน์ที่เจอออกมาให้ดู
> แล้วหยุด ไม่เดาส่งเดชแล้วเก็บของผิดลงฐาน — เอาบรรทัดนั้นมาบอกได้ เดี๋ยวเพิ่มให้

## 4. เอาข้อมูลไปเทรน

เปิด <http://localhost:8899> จะได้ JupyterLab (ไม่ต้องใส่รหัส)

เริ่มที่ `work/notebooks/01-สำรวจข้อมูล.ipynb` **ก่อนเสมอ** — ดูว่ามีข้อมูลกี่วัน
ขาดช่วงตรงไหน ค่าสมเหตุสมผลไหม แล้วค่อยเทรน

จากนั้นรันโมเดลตั้งต้น จะรันในเทอร์มินัลของ Jupyter หรือสั่งจากข้างนอกก็ได้

```bash
docker compose exec wx-lab python /home/jovyan/work/baseline.py --target barn_temp_c
```

จะได้ตารางแบบนี้

```
 ล่วงหน้า  แถวที่ใช้   ทายเท่าเดิม      โมเดล     ดีขึ้น
────────────────────────────────────────────────────────
    1 ชม.      1380        0.412      0.318     22.8% ✓
    6 ชม.      1375        1.847      1.203     34.9% ✓
   24 ชม.      1357        1.109      1.284    -15.8% ✗
```

**คอลัมน์ที่ต้องดูคือ “ดีขึ้น”** ไม่ใช่ค่าความคลาดเคลื่อนของโมเดล

เพราะอุณหภูมิอีกหนึ่งชั่วโมงข้างหน้าเกือบเท่ากับตอนนี้เสมอ โมเดลอะไรก็ตามที่แค่ทาย
ว่า “เท่าเดิม” ก็ได้ค่าความคลาดเคลื่อนต่ำจนดูเก่งแล้ว ถ้าไม่เทียบกับมัน จะเทรนโมเดล
ใหญ่ ๆ ได้ MAE 0.4 °C แล้วคิดว่าสำเร็จ ทั้งที่การทายว่าเท่าเดิมได้ 0.45 °C
— แปลว่าโมเดลทั้งตัวมีค่าเท่ากับศูนย์

เป้าหมายที่ทำนายได้ตอนนี้

| `--target` | ทำนายอะไร | ใช้ทำอะไรต่อ |
| --- | --- | --- |
| `barn_temp_c` | อุณหภูมิในเล้า | เตือนล่วงหน้าว่าจะร้อนเกินเกณฑ์ |
| `barn_thi` | ดัชนีความเครียดร้อนของสุกร | เตือนล่วงหน้าก่อนสุกรกินอาหารลดลง |
| `mast_temp_c` | อุณหภูมิข้างนอกที่ฟาร์ม | ปรับค่าพยากรณ์ทั่วไปให้ตรงกับจุดที่ฟาร์มตั้งอยู่ |
| `wx_temp_c` | อุณหภูมิของแบบจำลองโลก | **ไม่ได้ใช้งานจริง** — มีไว้ทดสอบว่าท่อทั้งเส้นทำงาน เพราะเป็นตัวเดียวที่มีข้อมูลเยอะพอตอนนี้ |

ผลของ `wx_temp_c` ตอนตั้งระบบ (9,732 ชั่วโมง) — ยืนยันว่าท่อตั้งแต่ฐานถึงโมเดลทำงานครบ

```
 ล่วงหน้า  แถวที่ใช้   ทายเท่าเดิม      โมเดล    ดีขึ้น
      1 ชม.       9732        0.578      0.389    32.8% ✓
      6 ชม.       9727        2.159      0.854    60.4% ✓
     12 ชม.       9721        2.928      0.881    69.9% ✓
     24 ชม.       9709        0.967      0.858    11.3% ✓
```

ที่ 24 ชม. ชนะน้อยกว่าเพื่อนเป็นเรื่องปกติ — การทายว่า "เท่าเดิม" แข็งแรงที่สุดตรงคาบ 24 ชม.
พอดี เพราะอุณหภูมิวนรอบวัน เวลาเดียวกันของเมื่อวานจึงใกล้เคียงของวันนี้อยู่แล้ว

## 4.5 ส่งคำทำนายขึ้นแดชบอร์ด

`baseline.py` ตอบว่า **"โมเดลเชื่อได้แค่ไหน"** — ย้อนไปวัดกับอดีตที่รู้คำตอบแล้ว
`predict.py` ตอบว่า **"อีกกี่ชั่วโมงข้างหน้าจะกี่องศา"** — ทำนายของจริงที่ยังไม่เกิด
แล้วเขียนทั้งสองอย่างลงไฟล์เดียวให้หน้าเว็บหยิบไปแสดง

```bash
# หน้าเว็บมีสามแท็บ ต้องสั่งทั้งสามค่า ไม่งั้นแท็บที่ขาดจะขึ้นว่า "ยังไม่เคยเทรน"
for t in mast_temp_c mast_rh mast_wind_ms; do
  docker compose exec wx-lab python /home/jovyan/scripts/predict.py --target $t
done
```

ได้ไฟล์ `lab/models/forecast-<ค่า>.json` ค่าละหนึ่งไฟล์ ข้างในมีคำทำนาย 9 ระยะ
(1·2·3·4·6·8·12·18·24 ชม.) · ค่าความคลาดเคลื่อนของแต่ละระยะ · ค่าที่เสาวัดได้ 48 ชม.
ย้อนหลัง · และคำพยากรณ์ของ Open-Meteo ช่วงเดียวกันไว้เทียบ

| `--target` | หน้าเว็บเรียกว่า | ตัวเทียบใน `fcst` |
| --- | --- | --- |
| `mast_temp_c` | อุณหภูมิ | `temp_c` |
| `mast_rh` | ความชื้น | `rh` |
| `mast_wind_ms` | ลม | `wind_ms` |

> เพิ่มค่าใหม่ที่ `TARGETS` ใน `predict.py` ที่เดียว แล้วเติมชื่อลงรายชื่อที่อนุญาต
> ใน `server/src/modules/forecast/route.js` กับแท็บใน `src/pages/Weather.jsx`

### แดชบอร์ดอ่านไฟล์ ไม่ได้ต่อฐานนี้ — และตั้งใจให้เป็นแบบนั้น

```
wx-lab  ──เขียน──►  lab/models/*.json  ──อ่านอย่างเดียว──►  swine-api  ──►  หน้าสภาพอากาศ
```

`compose` ของแดชบอร์ดผูกโฟลเดอร์ `weather/lab/models` เข้าไปที่ `swine-api` แบบ `:ro`
แล้วเปิดเส้นทาง `GET /api/forecast/model?target=…` ให้หน้าเว็บเรียก

ถ้าให้ `swine-api` ต่อ `wx-db` ตรง ๆ จะสะดวกกว่าตอนเขียน แต่ความแยกขาดที่ทั้งโฟลเดอร์นี้
ออกแบบมาเพื่อสิ่งนั้นจะหายไปทันที — วันที่ `docker compose down -v` เพื่อล้างคลังไปลองอะไร
หน้าเว็บของจริงจะพังตามไปด้วย ผูกเป็นไฟล์แทน คลังดับทั้งก้อนแล้วหน้าเว็บยังแสดง
คำทำนายครั้งล่าสุดได้ พร้อมบอกว่าคำนวณไว้เมื่อไร

### สองอย่างที่ `predict.py` ยอมเสียคะแนนเพื่อความซื่อสัตย์

1. **ตัดฟีเจอร์ `barn_*` ทิ้งทั้งตอนเทรนและตอนวัด** เซนเซอร์ในเล้าเงียบตั้งแต่
   8 ก.ย. 2569 08:31 ถ้าเทรนโดยใช้ค่าพวกนั้น โมเดลจะพึ่งมัน แล้วตอนทำนายจริงกลับไม่มีให้ใช้
   คะแนนในตารางจะสวยกว่าความแม่นจริงโดยไม่มีอะไรฟ้อง — **ตัวเลขที่ประกาศต้องมาจาก
   โมเดลตัวเดียวกับที่ใช้ทำนายจริง**
2. **ค่าล่าสุดเก่าเกิน 3 ชั่วโมง = ไม่ทำนายเลย** (`--stale-hours`) ทำนายจากค่าที่หยุด
   อัปเดตแล้วได้ตัวเลขที่หน้าตาปกติทุกอย่างแต่ผิด ซึ่งอันตรายกว่าการไม่มีตัวเลขให้ดู
3. **ดันค่าที่ทำนายกลับเข้าขอบที่เป็นไปได้จริง** (`bounds` ใน `TARGETS`) โมเดลไม่รู้ว่า
   ลมติดลบไม่ได้ ทำนายออกมาจริงแล้ว −0.02 m/s (10 ก.ย. 2569) ตัวเลขติดลบบนหน้าจอ
   ทำให้คนเลิกเชื่อทั้งการ์ด ทั้งที่โมเดลชนะทุกตัวเทียบ **ตัดตอนแสดงผลเท่านั้น
   ไม่ได้ไปยุ่งกับตอนวัดคะแนน** คะแนนจึงยังเป็นของจริง

> **ยังไม่มีตัวตั้งเวลาให้รันเอง** — ตอนนี้ต้องสั่งเองทุกครั้งที่อยากได้ของใหม่
> หน้าเว็บจึงบอกเวลาที่คำนวณไว้เสมอ คนดูจะได้รู้ว่ากำลังดูของเมื่อไร

## 6. สามเรื่องที่ออกแบบไว้กันพลาด — อย่าไปแก้ทิ้ง

### 6.1 พยากรณ์ต้องอยู่คนละตารางกับค่าที่เกิดขึ้นแล้ว

ตาราง `fcst` มีสองเวลา ไม่ใช่เวลาเดียว ถ้าเอาคำพยากรณ์ไปปนใน `obs` แล้วเทรน
จะเกิด **data leakage** — โมเดลได้เห็นค่าที่ ณ เวลาทำนายจริงยังไม่มีใครรู้
ผลคือคะแนนตอนทดสอบสวยมาก แต่ใช้จริงไม่ได้เลย และหาสาเหตุไม่เจอด้วย

ตอนสร้างชุดเทรน ให้เลือกเฉพาะแถวที่ `issued_at <= เวลาที่ทำนาย` — เขียนแบบนี้

```sql
-- คำพยากรณ์ "รุ่นล่าสุดที่ประกาศออกมาแล้ว ณ เวลา t" ของทุกชั่วโมงในอนาคต
select distinct on (f.measure, f.valid_at)
       f.valid_at, f.measure, f.value, f.issued_at
  from fcst f
 where f.station = 'openmeteo_kpp'
   and f.issued_at <= $1          -- $1 = เวลาที่จำลองว่ากำลังยืนอยู่
 order by f.measure, f.valid_at, f.issued_at desc;
```

`distinct on ... order by issued_at desc` คือหัวใจ — หยิบรุ่นที่ใหม่ที่สุด**ที่ออกมาแล้ว**
ไม่ใช่รุ่นที่แม่นที่สุดซึ่งมักจะออกมาทีหลังและยังไม่มีใครรู้ ณ ตอนนั้น

### 6.2 เก็บลงฐานเป็น UTC เสมอ

เก็บเป็นเวลาไทยตั้งแต่แรกคือกับดัก พอ join กับข้อมูลจากแหล่งที่เป็น UTC
จะเหลื่อมกัน 7 ชั่วโมงโดยไม่มีอะไรฟ้อง และกราฟยังดูสวยเหมือนเดิมทุกประการ
view แปลงเป็นเวลาไทยให้ตอนอ่านอยู่แล้ว

### 6.3 ค่าที่เชื่อไม่ได้ กรองตอนอ่าน ไม่ใช่ตอนเขียน

`obs` เก็บทุกอย่างตามที่แหล่งส่งมา รวมถึงค่าที่รู้ว่าผิด ส่วนการกรองอยู่ใน
`v_obs_clean` เพราะ *“เซนเซอร์ส่ง 0 มาตลอดตั้งแต่วันที่เท่าไรถึงวันที่เท่าไร”*
เป็นข้อเท็จจริงที่มีค่าในตัวมันเอง ทิ้งตั้งแต่ปากทางแล้วไม่เหลืออะไรให้สืบ

กติกาที่ใช้กรองตอนนี้

| ค่า | กติกา | เหตุผล |
| --- | --- | --- |
| CO₂ | ต่ำกว่า 250 ppm = ทิ้งทั้งวัน | อากาศกลางแจ้งทั้งโลกยังราว 420 ppm |
| NH₃ | ทิ้งตามวันที่ CO₂ พัง | มาจากโมดูลเดียวกัน |
| ตัวประกอบกำลัง | เป็น 0 = ทิ้ง | มีกำลังไฟไหลอยู่แต่ค่าเป็น 0 = มิเตอร์ไม่ได้วัด |
| **ทุกค่า** | ทั้งวันมีค่าที่ต่างกันแค่ค่าเดียว จากตัวอย่าง ≥ 50 ค่า = ทิ้งทั้งวัน | เซนเซอร์ค้างค่า — ค่าจากธรรมชาติไม่มีทางเท่ากันเป๊ะทั้งวัน (ยกเว้นฝน · ความสว่าง · พลังงานสะสม · ทิศลม ซึ่งนิ่งได้จริง) |

> กติกา CO₂ ต้องตรงกับ `src/lib/sensorHealth.js` ของแดชบอร์ด แก้ที่ไหนต้องแก้อีกที่ด้วย

**2. เสาอากาศของฟาร์มไม่มีประวัติเลย**
`/api/series` ของพี่เลี้ยงบีบข้อมูลจนใช้ไม่ได้ (ดูข้อ 3) และ feed นอกอาคารในฐานแดชบอร์ด
กลับเป็นคนละตัว (ดูข้างล่าง) ประวัติของเสาจึงเริ่มนับจากวันที่เปิดระบบนี้เท่านั้น
**ทางแก้ทางเดียวคือโหลด CSV จากเว็บพี่เลี้ยง** ตามขั้นตอนในข้อ 3

### เซนเซอร์นอกอาคารของฐานแดชบอร์ดตายอยู่ — แยกกักไว้แล้ว

ตรวจพบตอนตั้งระบบ เวลาเดียวกันเป๊ะ ๆ:

| แหล่ง | อุณหภูมิ | ความชื้น |
| --- | --- | --- |
| feed `outdoor_temperature` ของฐานแดชบอร์ด | 26.1 °C | 88.5 % |
| เสาอากาศของ PlotNexus | 32.3 °C | 59.3 % |

ต่างกัน **6 องศา** และ feed เก่า**ค้างที่ 26.10 °C เป๊ะ ๆ ติดกันอย่างน้อย 10 วัน**
(ทั้งวันมีค่าที่ต่างกันแค่ค่าเดียวจากตัวอย่างหลายร้อยค่า) = อุปกรณ์ตายแล้วค้างค่าสุดท้ายไว้

ถ้าเอาสองตัวนี้ยัดลงสถานีเดียวกัน ชุดข้อมูลจะมีขั้นบันได 6 องศาตรงรอยต่อของแหล่ง
แล้วโมเดลจะเรียนรู้ว่าเป็นการเปลี่ยนแปลงของอากาศจริง — **เสียทั้งชุดโดยไม่มีอะไรฟ้อง**

จึงแยกไปสถานี `kpp_out_legacy` ต่างหาก และ `v_obs_clean` กรองทิ้งอัตโนมัติด้วยกติกา

## 9. ข้อจำกัดที่ยังเหลือ

- **เก็บได้เฉพาะตอนเครื่องเปิด** — เหมือนกับระบบแดชบอร์ด ปิดเครื่องเมื่อไรข้อมูลขาดช่วง
  ทันที เรื่องนี้กระทบงานเทรนโมเดลหนักกว่าแดชบอร์ดมาก เพราะช่องว่างในข้อมูลทำให้
  สร้างตัวแปรย้อนหลังไม่ได้ทั้งช่วง ควรย้ายไปเครื่องที่เปิดตลอดก่อนเก็บข้อมูลจริงจัง
- **ยังไม่มีระบบสำรองข้อมูล** — `docker compose down -v` ลบทุกอย่างทันทีโดยไม่ถาม
- **ข้อมูลที่เทรนได้จริงมีแค่ 207 ชั่วโมง** ซึ่งยังน้อยเกินกว่าจะเชื่อผลของโมเดลได้
  (ดูข้อ 8) ต้องรอให้เก็บสะสมต่อ หรือโหลด CSV ย้อนหลังจากเว็บพี่เลี้ยงมาเติม
- **CO₂ · NH₃ ยังใช้ไม่ได้** เซนเซอร์ส่ง 0 มาตลอด จึงไม่มีตัวแปรคุณภาพอากาศให้โมเดลใช้
- **มีจุดติดตั้งเดียว** — เล้า R หลังเดียวกับเสาหนึ่งต้น โมเดลที่ได้จะใช้ได้กับฟาร์มนี้
  เท่านั้น จนกว่าจะมีฟาร์มที่สอง
